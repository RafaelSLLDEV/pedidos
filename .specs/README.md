# Specs do projeto

Cada mudança deve ter uma spec com quatro partes:

- contexto: por que a mudança é necessária;
- tarefa: o que deve ser feito;
- regras: restrições e decisões que devem ser respeitadas;
- definição de pronto: como verificar que a mudança foi concluída.

A pasta `.specs/` só entra no contexto de uma tarefa quando o agente for instruído explicitamente a ler a spec correspondente.
